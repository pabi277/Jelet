## Key dispute recorded (official key unchanged)

**Q39 (B)**, "inconsistent if a = b = c and p ≠ q ≠ r":
- With a = b = c = k, every left-hand side equals k(x+y+z). A solution would therefore need q−r = r−p = p−q. These three numbers sum to 0, so all would have to be 0, which forces p = q = r. Hence (B) is mathematically **true**.
- The same holds for k = 0 and under the reading p = r ≠ q.
- The official key lists only **A, C**. The stored key keeps the official A, C.
- `KEY_DISPUTES_2025` in the verifier records the extra true option. It is pinned to the official key [A, C], so the check fails if the key changes. Every run prints the dispute.
- The Q39 solution states the discrepancy openly.

**Q30:** the key B (1/3) relies on the "indistinguishable coins" convention, in which the 3 unordered outcomes are treated as equally likely. The solution notes that labelled fair coins would give 1/2.
