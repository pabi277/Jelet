# Phase 05 — JELET Study Hub (v3): Hardening, PWA & Launch Readiness Record

## 1. Summary

Phase 05 hardened the Phase 04 phone-first PWA into a **deployable, installable,
offline-capable, accessible** launch candidate. It added the installable PWA layer
(manifest + offline Service Worker + icons), closed edge cases (IndexedDB
fallbacks, routing, submit guards, session corruption), improved accessibility
(skip link, focus order, ARIA labels), audited production console/network hygiene,
and shipped deployment documentation. **Zero changes** were made to the verified
`_data/` corpus, the `1/12`-mark scoring logic (`assets/js/core/scoring.js`), or
the corpus loader semantics (`assets/js/core/data-loader.js`).

The work was committed incrementally in four slices, each verified against the
full gate suite before the next began.

---

## 2. Slice 1 — Installable PWA (manifest, Service Worker, icons)

- **`manifest.webmanifest`** — `name`/`short_name`, `display: standalone`,
  `theme_color`/`background_color` (`#0F6E66`), `start_url`/`scope` `./`,
  portrait orientation, 192×192 + 512×512 PNG icons (`any` + `any maskable`).
- **`sw.js`** — offline caching with four layers:
  - **Install:** precaches the full app shell (index.html, manifest, all CSS,
    all JS modules, icon sprite, PWA icons, vendored KaTeX JS+CSS) plus a
    **best-effort corpus precache** enumerated from `_data/manifest.json`
    (4 papers, 4 solution files, 42 unit workbooks, all 109 referenced SVGs).
    Any individual precache failure is skipped — install never blocks.
  - **Runtime:** stale-while-revalidate for same-origin GETs (figures, fonts,
    lazy corpus files) — first visit caches, later visits are instant offline.
  - **Navigations:** network-first with a cached-shell fallback (503 message
    if neither is available).
  - **Pass-through:** cross-origin requests (BYOK AI providers, YouTube
    facade) and all non-GET requests are never cached or blocked.
  - **Activate:** prunes stale caches by version prefix and `clients.claim()`.
- **`assets/icons/pwa-192.png` / `pwa-512.png`** — brand-teal rounded tile with
  a white "J" monogram, generated by **`scripts/make_pwa_icons.py`** (pure
  Python stdlib PNG writer, 4× supersampled AA — zero third-party deps).
- **`assets/js/app.js`** — `registerServiceWorker()` registers `./sw.js`
  (relative scope, subpath-safe), silently no-ops when SW is unsupported or
  the origin is not http(s), and toasts on pending SW updates.
- **`index.html`** — `<link rel="manifest">`, `apple-touch-icon`, PWA meta tags.

## 3. Slice 2 — IndexedDB hardening

`assets/js/db/indexeddb.js` was hardened so the app **never crashes** when
storage is unavailable:

- **`openDB()` never rejects.** If `indexedDB` is undefined, `indexedDB.open`
  throws, errors (private mode / blocked storage), or is `onblocked` by
  another tab (after a 1.5s grace wait), the module **transparently falls
  back to an in-memory session** (`MemObjectStore` adapter) with the same API
  surface — sessions, attempts, stats, bookmarks, and backup export/import
  all keep working for the current page lifetime.
- **`onupgradeneeded` is defensive:** stores/indexes are created only when
  missing; a failed upgrade degrades to memory mode rather than hanging.
- **`QuotaExceededError`** on writes (detected by `name`/`code 22`) sets a
  quota flag, emits a `quota-exceeded` sync notice, and rejects with a typed
  `StorageQuotaError` so views can react. `replaceStores` (backup import) is
  quota-guarded the same way.
- **UI:** `storageStatus()` / `isMemoryMode()` power a dismissible
  **"storage unavailable"** banner (`aria-live="polite"`) in `app.js`;
  quota events additionally toast. Styles are token-only (`shell.css`).

## 4. Slice 3 — Edge-case hardening

- **Routing:** new `isKnownRouteHash()` + redirect in `render()` — unknown or
  stale deep-linked hashes are normalized to `#/` (Today) via
  `location.replace`, never a blank screen.
- **Exam (`exam.js`):**
  - `finalizeSubmission()` wraps `submitSessionToAttempt` in try/catch and
    **re-arms** on failure (quota-aware toast, confirm button re-enabled) so a
    failed submission can be retried instead of leaving the runner locked.
  - Corrupted session records missing `title` are guarded.
  - Double-submit guards (`submitting` flag) were already present and remain.
- **Practice (`practice.js`):**
  - **Empty/corrupted pool guard** in `renderPracticeRunner` — a session whose
    questions all fail to resolve renders a clear "no questions" card instead
    of a blank runner.
  - **Double-submit guard** in `finishDrill` — disables the button, shows
    "Saving…", and on failure restores it with a quota-aware toast.
- **AI Tutor:** verified the BYOK flow already handles missing/invalid keys
  without throwing (missing key → 100% offline corpus mode; provider error →
  automatic verified-offline fallback with the error shown). The corpus-
  grounded offline path is independent of key state. No change needed.

## 5. Slice 4 — Accessibility

- **Skip-to-content link** (`index.html` + `shell.css`) — visible on keyboard
  focus, jumps straight to `#appMain`.
- **Global `:focus-visible` ring** on the shell; **restored the focus ring on
  search inputs** (`outline: none` previously killed it).
- **Closed bottom sheets leave the a11y tree** — `visibility: hidden` on
  closed sheets (timed with the slide transition) so keyboard focus can never
  enter an off-screen sheet; open sheets are fully focusable.
- **ARIA labels added:** bottom-nav tabs (`aria-label` per destination), OMR
  palette cells (state-aware: "Question 42, answered / marked for review /
  not answered"), practice option buttons, theme toggle. Sheet controls,
  figures (`role="img"` + `aria-label` via `mountFigure`), dialogs
  (`role="dialog" aria-modal`) were already present from Phase 04.
- **Keyboard focus order:** skip link → topbar → main content → open sheets
  → bottom nav — sane and predictable.

## 6. Slice 5 — Performance & correctness, deployment readiness

- **Console audit:** the only `console.*` in production code is one
  `console.warn` on the genuine IndexedDB error path (kept as a diagnostic —
  debug-gated behavior). **No stray `console.log`.**
- **Network audit:** all data fetches use relative `./_data/...` / `./assets/...`
  paths; **zero external CDN requests** — KaTeX + 20 fonts are fully vendored
  (enforced by `tests/pwa.test.mjs`). The only external requests are
  user-initiated BYOK AI calls (Gemini/Groq/OpenRouter) and the tap-to-load
  `youtube-nocookie.com` facade — both intentional and never auto-loaded.
- **`DEPLOY.md`** — static-host instructions (GitHub Pages, Netlify, Vercel,
  Cloudflare Pages, S3, Termux), the **hash-routing subpath note**
  (deep links work at `/<repo>/#/...` with zero config), SW/https
  requirements, CI gate list, and the frozen-corpus warning. `README.md`
  gained a "Running & Deploying" section pointing to it.
- **Subpath verification:** served the repo under `/Jelet/` via a static
  server and confirmed **all 160 corpus URLs + 18 shell assets return HTTP
  200** from the subpath — no absolute path breaks.

## 7. New automated gate: `tests/pwa.test.mjs` (5 tests)

Since this sandbox has no headless browser (Chromium/Playwright unavailable,
browser download hosts not reachable), the offline-PWA verification is done
rigorously in Node instead of DevTools:

1. Manifest parses and is installable (fields, 192/512 icons, PNG validity,
   declared-vs-actual size match).
2. `sw.js` parses; `SHELL_ASSETS` precaches the **complete** app shell and
   every precache URL exists on disk.
3. The SW's corpus-precache inventory resolves the **entire verified corpus**
   (manifest → papers/solutions/units/figures) on disk.
4. `index.html` wires the manifest + PWA meta; `app.js` registers `./sw.js`
   with an http(s) guard.
5. Zero external CDN requests — every `index.html` asset is relative, CSS has
   no `url(http...)`, and all vendored KaTeX font references resolve locally.

## 9. Trade-offs & Notes

- **Headless browser unavailable:** the phase brief asked for DevTools-style
  offline verification. This environment has no Chromium/Playwright and the
  sandbox network is restricted, so offline behavior is verified via the
  new `pwa.test.mjs` static/dynamic inventory gate plus an HTTP-level subpath
  smoke test. On a real deployment, re-confirm with DevTools → Application →
  Service Workers + Cache (offline reload of all 5 routes).
- **Memory-mode sessions are per-page-lifetime:** when IndexedDB is blocked
  (private mode), state survives navigation but not reload — this is
  inherent to the fallback and is clearly communicated by the storage banner.
- **SW caching is version-pinned** (`jelet-v3-sw-1`); a future cache-format
  change should bump the version string so activate() prunes old caches.
- **`scripts/make_pwa_icons.py`** is a committed regeneration tool; icons are
  committed PNGs, so no build step is required at deploy time.
